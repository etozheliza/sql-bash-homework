Часть 1. Работа с CSV

- Подсчёт количества строк в файле orders.csv
wc -l orders.csv
Эта команда показывает общее количество строк в файле. Используется для быстрой оценки объёма данных.

- Вывод первых 10 строк
head orders.csv
Команда выводит первые строки файла. Используется для проверки структуры данных и заголовков.

- Поиск строк со статусом PAID
grep "PAID" orders.csv
Фильтрует строки по ключевому слову. В данном случае позволяет найти все оплаченные заказы. 
Кол-во строк с PAID: 7

Часть 2. Анализ app.log

- Поиск ошибок (ERROR)
grep "ERROR" app.log
Позволяет найти все ошибки в логах.

- Количество ошибок
grep -c "ERROR" app.log
Возвращает число строк с ошибками.

- Последние 5 ошибок
grep "ERROR" app.log | tail -n 5
Позволяет увидеть последние ошибки по времени.

- Поиск медленных запросов (>2 секунд)
grep "duration=" app.log
Количество ошибок: 5; запросов, выполнявшихся более 2 сек: 2

Часть 3. SQL запросы

1) CROSS JOIN создаёт декартово произведение, где каждая строка одной таблицы соединяется с каждой строкой другой. Это проблема, если 1000 пользователей и 1000 товаров - будет 1000000 строк, что может "положить" базу

2) UNION без дубликатов возвращает уникальные user_id, дубликаты автоматически удаляются
UNION ALL возвращает все значения, включая повторяющиеся, одинаковые user_id могут встречаться несколько раз

Разница между UNION и UNION ALL в том, что:
UNION = уникальные значения (фильтрация дублей)
UNION ALL = все значения без изменений

Часть 4. Транзакция. 

Что происходит без COMMIT

Часть 6. баг в уже существующем коде.

1) SELECT * FROM Orders WHERE user_id = 1;

Лучше не использовать SELECT *, а явно указать нужные поля:
SELECT order_id, user_id, amount, status, created_at
FROM Orders
WHERE user_id = 1;

Чтобы ускорить поиск по user_id, можно добавить индекс:
CREATE INDEX idx_orders_user_id ON Orders(user_id);

Вместо того чтобы просматривать всю таблицу (full scan), база сразу находит нужные строки по user_id.

Минусы индекса:
замедляет INSERT / UPDATE / DELETE, потому что индекс тоже нужно обновлять
занимает дополнительное место в бд

2) SELECT u.name, o.order_id
FROM Users u
LEFT JOIN Orders o ON u.user_id = o.user_id
WHERE o.status = 'PAID';

Ошибка:
WHERE o.status = 'PAID' ломает LEFT JOIN. Запрос перестаёт быть LEFT JOIN и превращается в INNER JOIN, потому что: строки, где o.status = NULL, отбрасываются

Исправленный:
SELECT u.name, o.order_id
FROM Users u
LEFT JOIN Orders o
ON u.user_id = o.user_id
AND o.status = 'PAID';

Влияние этого бага на продукт: пользователи без оплаченных заказов просто не попадут в результат, бизнес может видеть неправильную или неполную статистику (например, меньше оплаченных заказов, чем есть на самом деле)
